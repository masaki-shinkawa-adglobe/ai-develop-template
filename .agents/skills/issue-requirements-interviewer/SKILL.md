# Issue Requirements Interviewer

要件を合意可能な実装単位へ分解し、確定した単位は会話を止めずに Issue 化する。実装は開始しない。

## 推奨モデル設定

直接呼び出しでは `gpt-5.6-sol` と reasoning effort `medium` を推奨する。直接呼び出し時は親モデルを切り替えられないため、実行中の親モデルがこの設定と異なっても警告や停止はしない。

## 開始時の調査

1. リポジトリ内の `AGENTS.md` をすべて読む。`git status --short` を記録し、利用者の未コミット変更には触れない。
2. `CONTEXT-MAP.md` があれば対象コンテキストを特定し、該当する `CONTEXT.md`、`docs/adr/`、ADR、関連コードとテストを読む。なければルートの `CONTEXT.md`、ADR、関連コードを探す。
3. 既存の open / closed Issue と PR を検索して、同一目的・依存関係・既存用語を把握する。コードで回答できる点は質問しない。
4. 調査で得た事実と推測を分け、推測は質問で確認する。

## ヒアリング

- 1 回の応答で質問は必ず 1 つだけにする。質問には必ず推奨回答を添え、選択肢を出す場合は推奨する選択肢を明示する。
- 目的、利用者、成功条件、対象外、データ・権限・障害時の扱い、依存関係、優先度を、未解決の分岐がなくなるまで深掘りする。
- 用語が `CONTEXT.md` と矛盾・曖昧・過負荷なら即座に指摘し、正確な用語を推奨する。必要に応じて具体的な境界ケースを 1 つ提示して確認する。
- 利用者の説明とコードが矛盾する場合は、該当箇所を示してどちらを正とするか質問する。
- 合意済みで実装可能な単位が得られた時点で直ちに Issue 化し、URL を返してから残りの質問を続ける。未確定の単位は起票しない。
- 終了条件は未解決の分岐がなくなること、または利用者が「完了」「以上」と明示すること。

## Issue 化

起票前に既存 Issue と比較する。

- 完全重複なら新規作成せず、既存 Issue に合意済みの差分を追記して URL を返す。
- 部分重複なら責務を重ならない単位に分割し、双方の本文の「関連 Issue」に相手の URL を追記する。依存関係は実際の先行方向にだけ設定し、相互依存を作らない。
- 優先度は影響範囲、緊急性、依存先、障害性から提案する。未回答なら `priority:medium` を付ける。`priority:critical` はサービス停止、重大なセキュリティ問題、またはデータ損失に限る。
- 起票または更新の前後で、対象 Issue の本文・ラベル・URL を確認する。

本文には必ず以下を含める。未確定事項を代入して起票してはならない。

```markdown
## 目的

## 利用シナリオ

## 完了条件

- [ ]

## 対象外

## 依存関係

## 関連 Issue

## 決定事項・前提

## 関連ドキュメント
```

各 Issue は一つのレビュー可能な責務に保つ。ドキュメント変更が前提となる実装 Issue には、後述のドキュメント更新 Issue の URL を依存関係として記載する。

## ドキュメントの扱い

会話中に用語や不可逆な設計判断が確定したときだけ、`CONTEXT.md` または ADR に記録する。`CONTEXT.md` は用語集に限定し、実装詳細や要件メモを入れない。ADR は変更困難で、背景なしには意外で、実際のトレードオフがある決定だけにする。

終了時、要件ドキュメント更新用 Issue を必ず作成し、次を行う。

1. 差分ごとに根拠となる決定を確認する。差分がない場合は、その事実と理由を Issue に記載する。
2. Issue 本文またはコメントに、現時点の完全なドキュメント差分を fenced `diff` として添付する。
3. 他の実装 Issue の「依存関係」にその Issue URL を追加する。
4. 開始時に、対象文書ごとの状態と Skill 自身が加えた hunks を記録する。添付を GitHub 上で確認後、復元直前に記録済みの差分以外の追加・変更がないことを確認し、Skill 自身の hunks だけを逆適用する。追加変更と競合する場合は復元せず、文書と残存差分を利用者へ報告する。利用者の既存変更、開始時に dirty だったパス、無関係なパスは変更・破棄しない。

## 終了

実装、PR 作成、レビュー、マージ、または `$issue-orchestrator` の起動は行わない。作成・更新した Issue を依存順、優先度、URL とともに簡潔に列挙し、未起票の未確定事項があれば明示する。
